# Decisions

- 2026-11-05: Base is Textual 4f09312 (Michael Morris's last commit), not the Textual 8 work in progress. Decided by Michael.
- 2026-11-05: Rust, gtk4-rs, libadwaita and WebKitGTK 6.0. Decided by Michael.
- 2026-11-05: Changes go straight to `main` after an independent subagent review. No PRs, because Michael does not want to close them. Decided by Michael ("review everything yourself").
- 2026-11-05: WebKitGTK's sandbox stays on. On Ubuntu 24.04 it needs an AppArmor profile that allows user namespaces (`packaging/apparmor/textual-gtk-dev`, the same shape as Ubuntu's epiphany profile). Michael loaded it on koya. A Flatpak needs nothing extra; a `.deb` would ship its own profile.
- 2026-11-05: A small template engine (`src/style/template.rs`) instead of a Mustache crate. Both `mustache` and `ramhorns` fail to parse `formattedMessageFragment`, which every message goes through, because it uses GRMustache's else clause. Details in `docs/research/templates.md`.
- 2026-11-05: `resources/styling` is upstream's `Sources/App/Resources/Styling`, copied unchanged, with the BSD notices in `resources/styling/LICENSE.md`.
- 2026-11-05: One deliberate rendering difference from Textual: a colour span still open on a message's last fragment is closed, so the HTML nests. Textual leaves it open in some cases; the result looks the same.
- 2026-11-05 (default, Michael can override): the name stays "textual-gtk" for now. The application ID is `io.github.androidkitkat.TextualGtk` until a name is chosen.
- 2026-11-05 (default, Michael can override): OTR is not decided until phase 3. Nothing in phases 1 and 2 depends on it.
- 2026-11-05 (default, Michael can override): keep Textual's structure and behaviour, drawn with libadwaita (header bar, Adwaita widgets) rather than copying macOS chrome.
- 2026-11-05: libadwaita stays, plus an appearance setting "Textual for Mac" that loads an extra stylesheet restyling the window chrome (sidebar, server list, member list, input bar) to look like the macOS app. Decided by Michael. Phase-2 widgets get stable CSS class names so the stylesheet needs no code changes; the setting itself lands with the preferences window in phase 3, matched against screenshots of the Mac app.
- 2026-11-05: The name is "Textual GTK". The application ID stays `io.github.androidkitkat.TextualGtk`, now final, so config paths will not need migrating. Decided by Michael.
- 2026-11-05: Rejoin after being kicked is Textual's global preference `RejoinChannelOnLocalKick`, off by default ("Automatically rejoin a channel when kicked"). Until the config file lands it is the `--rejoin-on-kick` flag. Textual also skips the rejoin when the channel's last join attempt failed; that condition waits for per-channel join-error state. Decided by Michael ("keep it a setting, copy Textual as much as possible").
- 2026-11-05: Copy Textual's behaviour and defaults as closely as possible; a different behaviour goes in only as a setting whose default is Textual's. Decided by Michael.
- 2026-11-05 (default, Michael can override): input history copies Textual, drafts included (Up or Down on unsent text keeps it as an entry), instead of the design's separate draft stash; scope is Textual's `SaveInputHistoryPerSelection`, off by default (one global history). The only fix is Textual's always-true repeat check. Details in phase2.md, unit 7.
- 2026-11-05 (default, Michael can override): the default leaving comment for QUIT, PART and `/close` is "Textual GTK", not Textual's "Textual IRC Client: www.textualapp.com".
- 2026-11-05 (default, Michael can override): Textual's two Return preferences map as Command to Super: Super+Return (or Super+Enter) sends the text as an action (`CommandReturnSendsMessageAsAction`, on), and Control with the keypad Enter sends (`ControlEnterSendsMessage`, off); Control with the main Return key stays a new line, as in Textual, where only the keypad Enter is bound. Flags `--command-return-sends-action` and `--control-enter-sends-message` until the config file.
- 2026-11-05: Two plain Textual bugs not copied in commands: `/mode #c +o x` sends the channel once (Textual repeats it), and a CTCP with no extra text ends `VERSION\x01`, not `VERSION \x01` (Textual formats an empty string with a space). Unknown commands keep Textual's `COMMAND ` trailing space, which servers ignore.
- 2026-11-05 (default, Michael can override): `/names` sends NAMES but its replies are not shown yet: Textual prints them in a "Hidden Responses" utility window, which comes with the phase-3 UI. Textual commands not yet implemented (the list is in phase2.md, unit 7) still go to the server uppercased, as unknown commands do in Textual.
